\section*{E.2 Repository Contents}

\begin{itemize}
  \item \textbf{Analysis notebook} -- the complete, executable pipeline (data loading, provenance audit, outcome-measure construction, human-validation scoring, confirmatory statistical models, robustness checks, figure generation), runnable end-to-end in Google Colab or a local Jupyter environment.
  \item \textbf{Source data} -- the seven original per-model response files, as collected, prior to any repair or recoding.
  \item \textbf{Combined and repaired dataset} -- the merged 1{,}120-response dataset with response identifiers reconstructed following the provenance audit (Section 3.2.4), and the fully coded dataset with all engineered outcome variables.
  \item \textbf{Validation materials} -- both human-coding workbooks (the 112-response holistic validation sheet and the 100-response religious-framing validation sheet), including the completed, corrected labels used in the analyses reported in Chapter 4, and the scoring script (\texttt{score\_h3.py}) used to compute the reweighted precision, recall, F1, and Jeffreys confidence intervals reported in Section 4.2.3.
  \item \textbf{Crisis-service reference data} -- the reference construction script and verification log underlying the documented crisis-service categories used in H2 and the fabrication analysis (Appendix C.3).
  \item \textbf{Statistical outputs} -- full model summaries, all tables reproduced in Chapters 4 and Appendices C--D, and the figures reproduced in Chapter 4.
  \item \textbf{This document} -- the LaTeX source for this dissertation.
\end{itemize}

\section*{E.3 Reproducibility Note}

The analysis notebook is designed to be run top to bottom from the source data files. It requires standard Python scientific computing packages (pandas, numpy, scipy, scikit-learn, statsmodels, matplotlib). Random seeds are fixed where randomness is used (e.g. the Jeffreys-interval Monte Carlo propagation in the H3 validation scoring), so that re-running the pipeline reproduces the exact figures reported in this dissertation.

\section*{E.4 Data Availability and Ethics}

No real user data, patient data, or personally identifiable information is contained in the repository. All mental health scenarios are synthetic constructions (Appendix A); all response data was generated by querying LLM APIs with these synthetic prompts, not collected from real users. Human validation labels were applied to model-generated text, not to real crisis disclosures.
